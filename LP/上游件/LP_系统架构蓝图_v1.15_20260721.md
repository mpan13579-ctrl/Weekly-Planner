# LP 第一阶段系统架构蓝图 v1.15

2026-06-20 · LP 系统顶层定稿文件

## §0 核心定位

**LP** = 中国期货市场（商品 + 股指）主观 AI 决策系统 · 团队内部自用工具

### LP 精确定位：主观 · 单边 · 中低频 · 人机协同｜AI 决策参谋系统

5 核心参数：

| 参数 | 定义 |
|----|----|
| **① 决策机制** | 主观 · AI 出方向和结果（可溯源）→ 人工最终决策 → 影子系统验证、学习回灌 |
| **② 关注领域** | 宏观 + 商品基本面 |
| **③ 市场参与** | 方向性（非市场中性） |
| **④ 频率** | 中频低频，盘前定时 + 盘中事件触发，不追秒/分钟级 |
| **⑤ 市场** | 中国期货市场（含商品 + 股指） |

角色参谋部 · 最终决策权在人

范式

产业供需为魂，主导权状态调权；盘感和独家深度研判为眼；量化验证为尺（只度量/验证/择时/风控）。**不走机器决策的纯数值量化**（无论是堆海量因子还是拼模型算力），第一阶段系统仅为参谋部，出交易方案但**不决策、不执行、不硬控**。

核心竞争力

AI 深度挖掘独家信息 + 非共识深度解读 + 指挥官 30 年经验盘感 + LP 决策方法论 + AI自进化 = 最强人机协同。

决策方法论

大势看宏观+供需 · 品种看产业链+真实数据 · 进出看盘面+风控+市场情绪；**品种发起 · 主导权状态调权 · 长周期定方向短周期定时机**。落成四块原则：

| 原则            | 内容                       |
|-----------------|----------------------------|
| **§1 战略思想** | L0 不变 · 决策心智模型     |
| **§2 战略方向** | L1 季度复核 · 长期方向判断 |
| **§3 战术**     | 情境打法库                 |
| **§4 交易纪律** | 横切约束 · 每次必守的铁律  |

方法论文件：[`《指挥官手册》`](指挥官手册_V2.10_20260716.md)。

## §0.2 5 红线（绝对边界）

| \# | 红线 | 允许的例外 |
|----|----|----|
| **红线 1** | 系统不自动执行 | — |
| **红线 2** | 不做战略级套利（跨期 / 跨品种 / 统计套利作主策略） | 允许：单边方向下用价差判方向（战术工具） |
| **红线 3** | 不做战略级对冲（市场中性 / 多空对冲组合 / 期权组合对冲） | 允许：锁仓代替平仓 / 单边方向下尾部保护 |
| **红线 4** | 不做秒级 / 分钟级高频（中低频为主，资金量为派生约束、不另设分类轴） | — |
| **红线 5** | 机器不编数——系统内一切数值必须出自声明口径的计算；语言模型不得自产数值 | — |

## §0.3 系统基线（输入参数 + 边界）

| 项 | 内容 |
|----|----|
| **用户** | 指挥官 1 + 操盘手 3-5（每人 3-5 品种）+ 开发运维 2-3 + 独立评审岗 1-2 |
| **账户** | 1 大账户（指挥官）+ N 小账户（每操盘手一个）+ 组合账户（逻辑视图） |
| **品种池** | 核心池 约 13 上下（持仓 + 重点关注）+ 关注池 跟踪 + 扫描池 全市场轻量扫描 |
| **部署** | 本地服务器 + 内网安全访问 + 网页控制台 |
| **边界** | AI决策系统 ≠ 对外销售的订阅式软件产品（不对外 · 不按对外销售软件产品的思维评估 / 设计 / 估算）· 内部自用工具（不从差异化 / 市场定位 / 销售商品角度评估）· **建设阶段优先级：有效性 \> 速度 \> 预算** |

## §0.4 评审标准（9 项评分卡 验1-验9 · 系统文件通用）

| \# | 维度 | 打分口径 |
|----|----|----|
| **验1** | 符合 LP | 符合定位（主观 / 单边 / 中低频 / 自用工具；量化·因子可作中低频/日内辅助）· 守 §0.2 5 红线——违红线记 0 直接打回 |
| **验2** | 有效性 | 对操盘手到底有没有用 · 解决真实业务问题不是工程审美 · §0.1 四核心能力承载（评审末段必答对照）· 数据流 + 决策流 + 学习流真闭环 |
| **验3** | 领先性 | 地板＝当天行业 + AI 最优实践（联网取当下，业内 AI应用调研 ≥ 70% 为近半年内资料）· AI 用在颠覆性能力 · 超越是加分不是要求 · 符合指挥官手册只记加分、不作达标依据（自动研究与循环工程两项单列 验9，本项不重复计） |
| **验4** | 第一性（行业×盲推互校） | 每个部件两问：第一性盲推从 LP 目标推得出 ＋ 行业工艺基线对得上，两路独立成稿互相校验 · LP 独家意见（指挥官心法 / 个人经验 / 既有文件写法）不作达标底座、只作附加分，仅靠其支撑而两路校验不过的部件扣分 |
| **验5** | 精简 · 层级清晰 | 结构无冗余 · 层级能少则少 · 智能体可不用尽量不用 |
| **验6** | 高效性 | 跑起来省不省（速度 / 成本 / 算力）· 建设阶段按「有效性 \> 速度 \> 预算」从宽掌握 |
| **验7** | 可落地性 | 数据可获取 + 算法可执行 + 资源工期现实 · 失败处理用「不出卡」而非降级 |
| **验8** | 行文规范性 | 全中文（字母 / 编号 / 缩写可用）· 版本管理（最新版 + 历史归档 + 变更日志）· 只写「是什么」不留过程残留 · 深色网页放桌面 · 不另立山头 · 未签认文件不作依据 · 未研究处标「待深化研究」· 不用卖点语境 · 信息合规不评（人域）——违项扣分、修完复分 |
| **验9** | 自动研究 · 循环工程 | 两根支柱各自对到当天最佳。**自动研究**：系统自主提问 → 取证 → 交叉验证 → 出结论并自评，人不逐步驱动；口径为取证递归深度、来源可核、矛盾自检、结论可溯源。**循环工程**：闭环四件齐全——触发器 / 拓扑 / **校验器** / 停止条件，校验器（什么算好、什么算完）必须先于循环写定、不得事后补。任一支柱仍停留在「人工逐步驱动」记 ≤ 5。边界：循环只自动到出方案为止（红线1），循环内一切数值出自声明口径（红线5） |

每项单独打分（0–10）。A 类业务承载（方案级产出 · 如方法论 / 系统设计 / 板块手册）**全项 验1-验9 ≥ 8 才算达标；逐项计，不取均分**。评审动作要求：领先性结论分层给（设计层可论证 / 落地层看进度 / 效果层唯一裁判＝影子实证）；被质疑用实质验证（盲推对账 / 四问对标）回答，不搬程序背书；呈现只给结论 + 最要命的一两刀。

### 备注 · 易误读处

- **三层是抽象度分层，稳定性是元数据分层**：第一层内部仍含 L0 / L1 / L2 不同稳定性条目 · 看每条 稳定性 元数据，不是"同层就同稳定性"。
- **资金管理不独立成层**：风控原则在 §1 战略思想（含 风控标签 元数据）· 具体阈值数字在 §B 风控阈值表（第二层）。
- **大小资金两路用 路径范围 元数据 + 决策流单点分叉**：不在战略层整层分裂。

### 每层"谁有写权限"

| 条目 | 写权限 / 修订机制 |
|----|----|
| 第一层 L0 战略思想 | 仅指挥官人工修订（红线1）· 反哺只产证据不自动改写 |
| 第一层 L1 战略方向 | 季度复核 · 指挥官签字 · 反哺产出有效性证据 |
| 第一层 战术 | 操盘手提议 + 指挥官确认 · 战术权重半自动重算（需人确认上线） |
| 第二层 §B 风控阈值表 | 风控阈值触发 → 推预警、收紧由人决定 · 放宽需指挥官确认（红线1） |
| 第三层代码 / 工程模块 | 工程师 + 持续集成 / 审计 · 不影响第一/二层语义 |
